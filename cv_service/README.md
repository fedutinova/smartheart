# cv_service — ECG rhythm classifier

Python (FastAPI + PyTorch) inference service for ECG rhythm classification.
Wraps the `ECGV9ContextResidual` model from the delivery bundle and exposes
two HTTP endpoints consumed by the Go backend (`back-api`).

## Endpoints

- `GET  /health`  — liveness + checkpoint status
- `POST /predict` — multipart form: `file`, `layout_label`, `preprocess_name`

`/predict` returns the structured rhythm prediction described in
[ecg_site_delivery_bundle/README.md](../ecg_site_delivery_bundle/README.md).
The `explain` branch (Bothub vision LLM) is intentionally **removed** —
medical explanation is generated by `back-api` via the project's existing
`gpt.Processor`.

## Checkpoint

The 89 MB `stage_oldv9_residual_best.pt` is **not committed**. Place it at:

    cv_service/models/stage_oldv9_residual_best.pt

A working copy is bundled at:

    ecg_site_delivery_bundle/models/stage_oldv9_residual_best.pt

For local dev you can symlink it:

    ln -s ../../ecg_site_delivery_bundle/models/stage_oldv9_residual_best.pt \
          cv_service/models/stage_oldv9_residual_best.pt

In docker-compose the file is mounted read-only from the host into the container.

## Run locally (without Docker)

    cd cv_service
    python -m venv .venv && source .venv/bin/activate
    pip install -r requirements.txt
    ./start_api.sh

## Run via docker-compose

    docker compose up cv

Healthcheck: `curl http://localhost:8001/health`
